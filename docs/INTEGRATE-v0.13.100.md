### v0.13.100 — 终端输入延迟根治：录制预算的全表 SUM 收进进程内缓存

> 触发：用户「嵌入式终端会话文字输入非常慢 很不正常」。
> **这不是终端的问题** —— 是终端录制（`TERM_RECORD=1`）在**每个按键、每帧输出**上
> 都跑了一遍无索引的全表聚合，而那个调用是**同步**挂在 asyncio 事件循环里的。

**根因**：`Recorder.feed()` 的全局预算检查是 `SELECT SUM(bytes) FROM term_recordings`。
`EXPLAIN QUERY PLAN` 实测 = `SCAN term_recordings`，**无索引可用**
（表上只有 `idx_termrec_sid(session_id, seq)`）。而 `feed()` 的两个调用点都在
事件循环里**同步执行**：

| 调用点 | 触发时机 | 频次 |
|---|---|---|
| `src/term.py:1221` | pty 读回调 `on_readable` | **每帧输出**（TUI 每键重画 K 屏 = K 次） |
| `src/term.py:1488` | WS 收包循环 | **每次按键** |

生产库（`/fs` 是 `trimafs` 卷）**44.7 万行 / 157MB**，单次 SUM **110~124ms**
⇒ 整个事件循环被独占上百毫秒，别的会话/WS/HTTP 一起卡。

**三层实测证据**：

1. 离线曲线（`work/probe-term-record-cost.py`）：
   1,040 行 0.21ms / 50,040 行 6.86ms / 150,040 行 16.83ms / **444,040 行 67.92ms**；
   同表下「去掉 SUM 的缓存口径」恒定 0.04~0.05ms ⇒ **1405 倍**。
2. 生产真机（直接测 `:3102`）：逐键 RTT **p50 677ms / max 784ms**。
3. 端到端 A/B（隔离影子 `:3207`，44 万行预置，两组**只差一个文件**）：
   **修复前 p50 56.54ms → 修复后 p50 0.24ms（236 倍）**。
   修复后 44 万行复测：feed p50 = **0.114ms**，30 帧内全表 SUM 次数 = **0**，
   缓存值与真值分毫不差。

**改法**：`total_bytes()` 加进程内缓存 `(字节数, 库路径)`。首次/换库后首次真查；
本进程每次成功 INSERT 按 `len(blob)`（脱敏**后**的落盘值）递增，写在 `if ok` 里
（**写失败不许推进缓存**）；任何 DELETE（`sweep()` / 同 sid 覆盖）**一律作废**
——增量法在有 DELETE 时会**永久偏高且不可逆**，所以不做减法修正（行数≠字节数）。
换库判据用 `db.current_path()`（实测 3µs，比它挡掉的 117ms 便宜四个数量级）；
**不用连接对象 id**（`init_db` 复用同一模块全局，id 会撞）。

**为什么保留 7 天保留期却还是 44 万行**：`sweep()` 只在 `Recorder.close()`（会话结束）
时跑，`post_sweep` 是没人调的手动端点；表最早一条 10-08 12:51，一天就长到 44 万行。
**本版不动这个设计**（属另一次范围变更），但必须记下：缓存把每帧成本从「随表线性」
压成常数，**表本身仍会长**。

**闸门**：新测试钉的不是命中率这种自我表扬的指标，而是四条会让预算失效的静默路径
（等价性/换库作废/DELETE 后回落/写失败不推进），外加一条**查询次数**判据
（20 帧 SUM 次数 ≤1）—— 用次数不用耗时，因为耗时随机器/卷变化，拿它当判据就是拿噪声当证据。
**红向自证 3 向均精确转红且各只红对应一条**：① 退回每帧真查 → `20 not ≤ 1`；
② `sweep` 漏作废 → `13 != 0`；③ 换库不判失效 → `80 != 0`。
回归：L0 1410 例 0 失败 0 跳过 / L1 64/64 / 收集器对账 1474=1474 / prepush 六闸全绿。

### ⚠ 施工期踩的三个坑（判别成本很高）

1. **`src/config.py:8-10` 是 `load_dotenv(override=True)`** ⇒ `.env` **覆盖进程环境变量**。
   影子实例传 `TERM_RECORD=0 / PORT=3206 / DATA_DIR=…` 会被生产 `.env` 全部盖掉，
   两组 A/B 实际都跑在生产库上（证据：两组 `record_enabled` 都 True、影子目录空、
   生产 `agents.db-wal` 在长）。**做隔离 A/B 必须给影子自己的 `.env`。**
2. **`run_dualstack.py` 的 `ENV_FILE` 是硬编码绝对路径**（指向生产 `.env`），
   不改副本那一行，影子会去 bind **生产 3102**。且本 shell 本身就继承了
   `PORT=3102 / DATA_DIR=<生产> / TERM_RECORD=1`，要用 `env -u` 逐个摘掉。
3. **worktree 里没有 `venv`**（gitignore 未跟踪），而 `scripts/run_tests.sh:19-20`
   在 `[ -x venv/bin/python ]` 不成立时**静默回退系统 `python3`** ⇒
   `ModuleNotFoundError: starlette` 刷出 47 个 error、收集器对账 828≠791，
   **看着像「我的改动炸了」其实不是**。跑 worktree 闸门必须
   `HUB_VENV=<主树>/venv/bin/python3`。
